# Core Rules

1. Understand before modifying.
2. One fact → one source of truth.
3. Reuse before creating.
4. Prefer the smallest sound solution.
5. Preserve working behavior unless the requirement requires change.
6. Never invent requirements.
7. Never fake test results.
8. Never hide errors.
9. Never silently expand scope.
10. Keep architecture/documentation synchronized when durable behavior changes.
11. Verify before declaring completion.
